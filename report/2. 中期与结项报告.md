# 一、项目概述 
## 1. 项目背景
<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">       湘潭大学校园占地面积较大，建筑分布分散，且校内道路、楼宇命名体系对新生、访客甚至部分教职工而言较为复杂，传统的纸质地图、人工问路等方式已无法满足高效、便捷的导航需求。同时，随着数字化校园建设的推进，校园场景下的智能化、可视化服务成为提升校园管理效率和师生体验的核心方向</font>。  为了让同学们更好的找到对应的地点坐标，参观校园，本项目旨在基于现有的前端导航逻辑，通过引入后端与空间数据库，将湘大校园导航升级为具备3D建筑展示、动态路径规划和地点信息维护功能的综合系统 ，解决校园导航痛点  。同时本项目在导航系统之外拓展了失物寻找功能，用户可通过本项目发布或寻找遗失物品。

## 2. 系统目标
+ 实现基于 PostGIS 的 3D 建筑数据存储与高度渲染。
+ 构建支持动态拥挤度调整的 Dijkstra 最短路径算法。
+ 开发管理员后台，支持地点图片上传与地理坐标维护。
+ 支持多个个性化功能，如对应地点失物招领，对应建筑同学点评。
+ 地图视角控制，点击某个地点后，视角可平滑移动聚焦于此。
+ 管理员可登录后台修改地点描述、坐标及路网信息。
+ 支持对应地点信息查询。
+ 筛选功能，让用户选择想看内容。
+ 详情面板实现，当点击3D建筑后，展示数据库里的描述，图像等信息。
+ 完成相应式适配，支持电脑，手机等不同设备的互通使用。

# 三、系统设计  
## 1. 系统架构
### 1.1 总体架构
本系统采用经典 B/S 三层架构，分为前端展示层、后端服务层、数据持久层，各层职责清晰、松耦合。



| **层次** | **技术组成** | **职责说明** |
| --- | --- | --- |
| 前端展示层 | MapLibre GL JS · 原生JS · HTML/CSS | 地图渲染（WebGL/3D）、UI交互、路径可视化、管理面板 |
| 后端服务层 | Node.js 22 · Express 5 · Multer | REST API、权限鉴权、路径算法调度、图片上传处理 |
| 数据持久层 | PostgreSQL 16 · PostGIS 3 | 地点/路网/照片/评论/失物招领数据持久化，空间索引 |


### 1.2 请求流程
完整请求链路如下（以路径规划为例）：

+ 浏览器前端发起 GET /api/navigation/route?start=1&end=10
+ Express 路由匹配，读取服务器当前小时判断时段（早/中/晚）
+ 查询 view_bidirectional_paths 视图，获取带时段权重的全量边数据
+ 调用 navigation.js（ngraph.path 封装）执行 Dijkstra 最短路径
+ 反查 locations 表获取路径节点经纬度坐标
+ 返回 JSON：{ period, pathNodes, coordinates, totalCost }
+ 前端使用 MapLibre GL JS 在地图上绘制粉色路线并弹出信息条

### 3.1 实体关系概览
系统数据库基于 PostgreSQL 16 + PostGIS 3，共 5 张业务表和 1 个双向路径视图。



| **表名** | **中文含义** | **核心说明** |
| :---: | --- | --- |
| locations | 地点/建筑 | 核心主表，存储3D建筑高度、经纬度、分类描述 |
| edges | 路网边 | 双节点路段，含早中晚三时段流量系数 |
| location_photos | 地点照片 | 多张图片与地点关联，支持is_primary首图 |
| location_reviews | 地点评论 | 用户点评，含审核状态（0待审/1显示/2屏蔽） |
| lost_and_found | 失物招领 | 挂失/招领信息，含状态流转 |
| view_bidirectional_paths | 双向路径视图 | edges的UNION ALL自反视图，自动生成反向路径 |


### 3.2 各表字段详解
### **<font style="color:#444444;">locations — 地点主表</font>**
| **字段** | **类型** | **约束** | **说明** |
| --- | --- | :---: | --- |
| id | SERIAL | PK | 主键，自增 |
| name | VARCHAR(100) | NOT NULL | 建筑/地点名称 |
| category | VARCHAR(50) |  | 分类（教学楼/食堂/宿舍/操场等） |
| description | TEXT |  | 详细描述 |
| longitude | DECIMAL(10,7) |  | 经度（WGS84） |
| latitude | DECIMAL(10,7) |  | 纬度（WGS84） |
| height | DECIMAL(5,2) | DEFAULT 0 | 建筑高度（米），用于3D拔高渲染 |
| min_height | DECIMAL(5,2) | DEFAULT 0 | 离地高度，支持天桥等悬空建筑 |


### **<font style="color:#444444;">edges — 路网边表</font>**
| **字段** | **类型** | **约束** | **说明** |
| --- | --- | :---: | --- |
| id | SERIAL | PK | 主键 |
| source_node | INTEGER | FK→locations | 路段起点，级联删除 |
| target_node | INTEGER | FK→locations | 路段终点，级联删除 |
| distance | DECIMAL(10,2) |  | 路段物理距离（米） |
| road_name | VARCHAR(50) |  | 道路名称（可选） |
| geom | GEOMETRY | SRID 4326 | PostGIS线几何，用于精确路径绘制 |
| flow_morning | DECIMAL(3,2) | DEFAULT 1.0 | 早高峰（6-11时）拥挤系数 |
| flow_noon | DECIMAL(3,2) | DEFAULT 1.0 | 平峰（11-17时）拥挤系数 |
| flow_evening | DECIMAL(3,2) | DEFAULT 1.0 | 晚高峰（17-22时）拥挤系数 |


### **<font style="color:#444444;">view_bidirectional_paths — 双向路径视图（核心）</font>**
由于路网物理边只存储单向，但行人可双向通行，通过 UNION ALL 将每条边扩展为正反两条，并同时计算三时段综合代价字段：

<font style="color:#333333;">cost_morning = distance × flow_morning</font>

<font style="color:#333333;">cost_noon    = distance × flow_noon</font>

<font style="color:#333333;">cost_evening = distance × flow_evening</font>

路径算法查询此视图，无需修改底层 edges 表即可获得双向路网数据。



### 3.3 关键索引
| **索引名** | **目标表.字段** | **作用** |
| --- | --- | --- |
| idx_edges_source | edges.source_node | 加速起点查询 |
| idx_edges_target | edges.target_node | 加速终点查询 |
| PostGIS空间索引（GIST） | edges.geom | 加速空间范围查询 |

# 四、系统实现  
## 1. 关键技术
路径规划核心使用 ngraph.path 库实现 Dijkstra 算法，结合服务器当前时间自动选择拥挤系数字段，使路径权重动态反映现实通行代价。



**时段判断逻辑（index.js）：**

<font style="color:#333333;">const hour = new Date().getHours();</font>

<font style="color:#333333;">let costField = 'flow_noon';                        // 默认平峰</font>

<font style="color:#333333;">if (hour >= 6  && hour < 11) costField = 'flow_morning';  // 早高峰</font>

<font style="color:#333333;">else if (hour >= 17 && hour < 22) costField = 'flow_evening'; // 晚高峰</font>



<font style="color:#333333;">// 从视图查询带当前时段权重的边</font>

<font style="color:#333333;">const { rows: edges } = await pool.query(</font>

<font style="color:#333333;">  `SELECT source_node, target_node,</font>

<font style="color:#333333;">          ${costField} as weight</font>

<font style="color:#333333;">   FROM view_bidirectional_paths`</font>

<font style="color:#333333;">);</font>

<font style="color:#333333;">const result = findShortestPath(edges, startId, endId);</font>



**路径结果返回格式：**

<font style="color:#333333;">{</font>

<font style="color:#333333;">  period: 'flow_morning',         // 当前使用的时段字段</font>

<font style="color:#333333;">  pathNodes: [1, 5, 8, 10],       // 途经节点ID列表</font>

<font style="color:#333333;">  coordinates: [[lon,lat], ...],  // 对应经纬度坐标</font>

<font style="color:#333333;">  totalCost: 312.5                // 综合代价（距离×拥挤系数）</font>

<font style="color:#333333;">}</font>

## 3.2 地点详情聚合查询
使用 PostgreSQL 子查询 + json_agg() 一次性聚合地点的照片、已审核评论、已发布失物招领，避免 N+1 查询问题：

<font style="color:#333333;">SELECT l.*,</font>

<font style="color:#333333;">  COALESCE(</font>

<font style="color:#333333;">    (SELECT json_agg(p) FROM location_photos p</font>

<font style="color:#333333;">     WHERE p.location_id = l.id), '[]'</font>

<font style="color:#333333;">  ) as photos,</font>

<font style="color:#333333;">  COALESCE(</font>

<font style="color:#333333;">    (SELECT json_agg(r) FROM location_reviews r</font>

<font style="color:#333333;">     WHERE r.location_id = l.id AND r.status = 1), '[]'</font>

<font style="color:#333333;">  ) as reviews,</font>

<font style="color:#333333;">  COALESCE(</font>

<font style="color:#333333;">    (SELECT json_agg(lf) FROM lost_and_found lf</font>

<font style="color:#333333;">     WHERE lf.location_id = l.id AND lf.status = 1), '[]'</font>

<font style="color:#333333;">  ) as lost_found</font>

<font style="color:#333333;">FROM locations l WHERE l.id = $1</font>

## 3.4序列同步自愈机制
当数据通过 migrate.js 批量导入指定 id 时，PostgreSQL 的 SERIAL 序列可能与实际最大 id 不同步，导致后续插入主键冲突。后端通过捕获异常 + setval 自动修复：

<font style="color:#333333;">try {</font>

<font style="color:#333333;">  result = await pool.query(</font>INSERT INTO locations (...) VALUES (...) RETURNING <font style="color:#333333;">, [...]);</font>

<font style="color:#333333;">} catch (innerErr) {</font>

<font style="color:#333333;">  if (innerErr.code === '23505') {  // 主键冲突错误码</font>

<font style="color:#333333;">    // 修复序列：将序列值同步到当前最大id</font>

<font style="color:#333333;">    await pool.query(</font>

<font style="color:#333333;">      `SELECT setval(</font>

<font style="color:#333333;">         pg_get_serial_sequence('locations','id'),</font>

<font style="color:#333333;">         (SELECT MAX(id) FROM locations)</font>

<font style="color:#333333;">       )`</font>

<font style="color:#333333;">    );</font>

<font style="color:#333333;">    // 重试插入</font>

<font style="color:#333333;">    result = await pool.query(</font>INSERT INTO locations (...) VALUES (...) RETURNING <font style="color:#333333;">, [...]);</font>

<font style="color:#333333;">  } else { throw innerErr; }</font>

<font style="color:#333333;">}</font>



## 3.5 边接口的双格式兼容设计
边的删除/更新接口兼容两种 id 格式：纯数字 id（有 id 列的表）和 source:target 复合键（无 id 列时前端传入），通过解析 ':' 分隔符区分：

<font style="color:#333333;">const raw = decodeURIComponent(req.params.id);</font>

<font style="color:#333333;">if (raw.includes(':')) {</font>

<font style="color:#333333;">  // 复合键格式：'5:8'</font>

<font style="color:#333333;">  const [src, tgt] = raw.split(':').map(Number);</font>

<font style="color:#333333;">  await pool.query('DELETE FROM edges WHERE source_node=</font>$ 1 AND target_node= $<font style="color:#333333;">2', [src, tgt]);</font>

<font style="color:#333333;">} else {</font>

<font style="color:#333333;">  // 纯id格式：'12'</font>

<font style="color:#333333;">  await pool.query('DELETE FROM edges WHERE id=$1', [parseInt(raw)]);</font>

<font style="color:#333333;">}</font>

### 3.2 常见问题排查
| **现象** | **解决方案** |
| --- | --- |
| 数据库连接失败 | 检查 .env 中 DB_PASSWORD / DB_HOST 是否正确；确认 PostgreSQL 服务已启动 |
| INSERT 主键冲突 | 已内置自愈：系统自动执行 setval 修复序列后重试，无需手动干预 |
| 路径计算失败 | 确认 edges 表中存在连接起终点的路径；检查 view_bidirectional_paths 视图是否已创建 |
| 图片访问404 | 确认 navi-server/uploads/ 目录存在且可写；检查图片URL前缀是否为 /uploads/ |
| 管理员403 | 检查前端请求 Header 中 x-admin-token 是否与 .env ADMIN_SECRET_KEY 完全一致 |
| 地图不显示 | 确认浏览器支持 WebGL（chrome://gpu 检查）；检查 MapLibre GL JS CDN 网络可达性 |

## 七、项目总结 
### 1. 成果总结
1. 核心功能落地，满足校园基础导航需求  
基于校园场景完成了导航系统的核心骨架搭建，实现了校园关键 POINT（教学楼、食堂、宿舍、图书馆、行政楼等）的地理信息录入、定位展示，以及步行出行方式的路径规划能力，能够满足师生日常校园内 “找地点、查路线” 的核心诉求。
2. 技术架构初步成型，具备迭代基础  
完成了前端地图可视化、后端地理数据接口、数据库存储等核心模块的开发，代码具备基础的模块化拆分逻辑；通过分支进行功能迭代管理，为后续功能扩展奠定了技术基础。
3. 基础数据体系搭建  
梳理并构建了湘潭大学校园地理信息基础数据库，完成了核心 POI 的坐标、名称、分类、简介等信息的结构化存储，为后续数据更新、功能扩展提供了数据支撑。

### 2. 不足与改进方向
### 不足
   缺少个性化导航功能（如无障碍路线规划、校园临时活动地点导航、晚自习教室 / 空闲场馆导航）；

   当前导航只涉及步行导航，没有考虑骑车或开车出行的不便。

### 改进
  后续可接入学校端口，丰富个性化的导航，列举更多信息。

  可考虑增添出行方式选择，新添骑车，开车等不同模式的地图导航。

1 引言
1.1 编写目的
本测试计划用于规范湘潭大学导航系统整体测试工作，明确测试范围、测试环境、测试内容、测试进度、资源安排及风险管控，指导后续测试用例设计、测试执行、缺陷管理与测试总结，保证系统功能、性能、兼容性、稳定性达到上线交付标准。
1.2 项目背景
湘潭大学导航系统基于 HTML+CSS+JavaScript + Node.js 开发，集成 Dijkstra 最短路径算法、校园地图展示、3D 导航页面、后端数据服务、校园点位数据管理等功能，面向校内师生实现校园景点路径规划与地图导航服务。
2 测试目标
1. 验证系统前端页面、地图展示、3D 页面、路径规划算法功能正确性；
2. 验证后端服务启动、依赖安装、数据库初始化、接口调用可用性；
3. 验证系统在主流浏览器下的兼容性；
4. 验证前后端联调全业务流程稳定性；
5. 发现系统潜在缺陷、界面问题、逻辑漏洞，推动修复闭环，保障项目可正常交付。
3 测试范围
3.1 功能测试范围
1. 前端模块：首页加载、校园地图渲染、地图缩放拖拽、点位选择、路径规划、3D 导航页面；
2. 算法模块：Dijkstra 最短路径计算逻辑正确性；
3. 后端模块：Node 服务启动、依赖安装、环境配置、数据迁移、数据库导入、API 接口请求；
4. 异常场景：起点终点相同、无可达路径、后端服务断开、网络异常。
3.2 非功能测试范围
1. 浏览器兼容性：Chrome、Edge桌面端；
2. 页面性能：首屏加载速度、静态资源加载完整性；
3. 系统稳定性：连续操作无崩溃、无控制台报错。
1. 服务器运维部署、域名配置；
2. 第三方浏览器小众版本、老旧 IE 浏览器适配；
3. 高并发压力测试。
4 测试环境
4.1 硬件环境
● 测试电脑：Windows 10/11 台式机 / 笔记本
● 网络环境：校园网 / 家用宽带 正常外网访问
4.2 软件环境
● 浏览器：Chrome、Microsoft Edge 最新版
● 运行环境：Node.js 18.x 版本
● 数据库：MySQL 8.0
● 辅助工具：Git、VSCode、浏览器开发者工具、Navicat
5 测试类型与测试策略
1. 黑盒测试：以功能业务为主，不关注代码内部逻辑，按业务流程设计用例执行；
2. 静态页面测试：直接本地打开 HTML 文件，验证界面、资源、基础交互；
3. 接口测试：验证后端 API 返回数据格式、状态码、内容正确性；
4. 兼容性测试：多浏览器统一验证核心功能一致性。
